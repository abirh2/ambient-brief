# Living World — data and interaction contracts

Status: **draft**, version **0.1**, 2026-11-02; approval pending. Companion to [00](00-product-vision.md), [02](02-functional-requirements.md) and [08](08-acceptance-criteria.md). E = audited/source-verified behavior; V = approved product direction; N = proposed new requirement. This defines observable contracts, not technical architecture, TypeScript interfaces or a provider migration.

## Data ownership and preservation

[Current data contracts](../docs/data-contracts.md) is authoritative audit evidence. Its limitations remain limitations until separately corrected and verified. Do not assume the unused generic RemoteState type is already the active application contract.

**DI-01 — Ownership/security (P0, E preservation).** Domain providers/stores/hooks and the existing application coordinator own requests, validation, refresh, cache and cancellation. The 3D renderer consumes normalized state only. It may not fetch providers, parse wire responses, dispatch Actions, own provider polling or remount data ownership per landmark/mode. HTML and scenery must agree on the same accepted domain/context state. Preserve existing deployment/base-path handling and public snapshot schemas unless an explicit reviewed change is required.

| Data / F baseline | Preserved owner and source | Runtime boundary |
| --- | --- | --- |
| Clock F01 | Device clock/Intl, selected timezone | Not network-synchronized; independent of world rendering |
| Location F02 | Browser consent, Open-Meteo search; BigDataCloud device reverse naming | No continuous tracking; reverse endpoint only for consented current-device coordinates |
| Weather/forecast/UV/daylight F03/F04/F10 | Open-Meteo browser adapters and weather hook | One weather response; no new astronomy/forecast request |
| Alerts F05 | Official NWS browser provider/hook | US country gate; unknown/non-US is unsupported, not checked-clear |
| AQI F09 | Open-Meteo AQI adapter/hook | US AQI/pollutants; general deterministic guidance |
| News F07 | Currents → Actions/Node → validated `public/data/news-feed.json` → Pages/browser | Bearer key only in producer; browser reads BASE_URL-relative file |
| Markets F08 | Finnhub → Actions/Node → `market-data` branch → public snapshot client | Header secret only in producer; no browser provider quote or workflow token |
| Currency F11 | Frankfurter v1 browser adapter/store | Daily reference/date semantics, not intraday; compatibility unverified |
| Prayer/Hijri F12 | AlAdhan adapter/service/store | Location/date/method/school-calculated schedule, not a live sensor |

Current producer schedules remain owned by YAML, not this product specification. The audit identified README drift: markets use minutes 11/26/41/56 in YAML, while README says 7/22/37/52. Similarly, old-news stale scanning can recheck static JSON each minute despite README's general polling description. Neither discrepancy authorizes scheduling or README edits in this task. No new network polling interval is introduced by the world.

## Identity, provenance and freshness

**DI-02 — Context identity (P0, N; R01/R02).** Before any visible reading changes context, associate the value with the request's complete relevant identity. Labels and values are accepted together. On settings changes, show only matching validated cache or loading/unavailable in the new context; old-context values may not remain in the primary reading, panel, countdown, alert banner or scene. Abort/supersede old requests; completion after cancellation cannot publish data, error, timestamp or loading changes into the newer context. Invalid restored IANA timezones need a disclosed safe fallback and correction action rather than silent location/time mismatch. Retain existing cache-key precision unless separately reviewed, while preventing presentation identity collisions.

| Domain | Required identity/context |
| --- | --- |
| Clock | Selected location identity + validated/disclosed timezone + time format; device time |
| Weather/hourly/UV/daylight | Location coordinates/identity, requested temperature/wind units, timezone, forecast date/hour context |
| AQI | Location coordinates/identity, US AQI scale, pollutant units and measurement-time interpretation |
| Alerts | Location coordinates/identity + normalized country/coverage + alert stable ID + validity interval |
| News | Enabled topic set and active topic; feed version/provider; each story's stable ID/categories/publishedAt |
| Markets | Snapshot/provider/version, symbol/type/proxyFor, USD, generatedAt and per-symbol source/stale state; selected display symbols |
| Currency | Requested and validated response base/quote, positive finite rate, reference date; list support metadata separately |
| Prayer/Hijri | Coordinates/location, timezone, local Gregorian schedule date, calculation method and Asr school; today/tomorrow identities independently |

Time format alone reformats, not refetches, existing time data. Company display selection does not request new quotes. Location changes invalidate weather/AQI/alerts/prayer, units invalidate weather, topics invalidate affected news selection, pair/enablement invalidates currency, prayer method/school/enablement invalidates prayer, market enablement affects market work. Appearance/mode/camera changes cause no domain request.

**DI-03 — Provenance record (P0, N; R03).** For every external reading used by HTML or world presentation retain, where available: accepted context, source/provider, value/units, source observation or publication/reference/schedule date, browser successful-fetch time, last check attempt/result, cache origin and freshness classification. Unknown fields remain unknown. These are information obligations, not an instruction to invent a common wire schema. Successful-fetch means a validated network result; cache read, failure, cancellation and scene transition never advance it. Producer generatedAt, story publishedAt, quote providerTimestamp, reference date and browser fetch/check times must remain distinct.

Local-without-offset weather/AQI timestamps require selected/provider timezone semantics, not device-local parsing. Do not synthesize an exact observed instant from condition text or browser fetchedAt. Null quote timestamp stays unknown. News v1 cannot supply a carried bucket's last-success time: show partial/feed-level age with category refresh age unknown. A reviewed schema extension could improve metadata later; it is not required to invent precision now.

**DI-04 — Freshness classification (P0, N; R03).** Every external value is internally classified using the existing vocabulary below. Origin, coverage/loading/error/partial and age are additional dimensions. Expose a short adjacent qualifier when a reading is cached/stale/delayed/reference/demo/unavailable, with full source/time detail reachable by keyboard/tap in the same mode. One global badge cannot substitute for qualifiers on affected readings. A shared weather qualifier can cover weather/forecast/UV/sunset only if its scope is explicit. Price rows retain row status.

| Classification | Meaning / allowed use |
| --- | --- |
| `live` | Source/context/timing support a current claim; never inferred from HTTP success, hook `loaded`, fresh cache or producer `fresh`. No numeric real-time market guarantee is authorized |
| `delayed` | Valid source data with known delay, scheduled snapshots, or unverified observation timing; explain “source timing unknown” where needed rather than invent delay minutes |
| `end-of-day` | Dated daily reference, including currency; visible wording “Reference · [date]” avoids claiming an exact market close |
| `cached` | Retrieved/retained validated cached data within permitted context/retention; source generation/reference age still shown and may add delayed/stale qualifiers |
| `stale` | Beyond source/domain freshness, retained failure fallback or producer stale value; original time/age remains visible |
| `unavailable` | No usable correctly contextualized value; placeholders with reason, never realistic mock numbers |
| `demo` | Explicit development-only simulation, visibly labeled through HTML and scene; excluded from production |

When multiple conditions apply, demo/unavailable take precedence; otherwise stale takes precedence over cached, cached over reference/delayed, and reference/delayed over a possible live claim. Keep secondary qualifiers (for example cached daily reference dated Friday). Partial is independent and never erases stale row/bucket concerns. Weather/AQI without reliable observation metadata are conservatively delayed with known fetch age/unknown observation time. Prayer displays calculated schedule/date and cache state; network acquisition does not make the calculation a live observation. Device clock is local device provenance, not an external-value freshness claim.

**DI-05 — Effective freshness/retention baseline (P0, E preservation + N explicit enforcement).** Use active domain policies recorded below, not similarly named unused constants. Preserve last-good data only for matching identity and accepted validity. Corrupt values are not fallbacks. Hardening exceptions are IG-01–IG-04 and DI-08/DI-09, explicitly proposed corrections. Any other retention/cadence change needs a reviewed revision.

| Domain | Audited active fresh period | Stale/failure constraints and source age |
| --- | --- | --- |
| Weather + hourly/UV/sunset | 15 min | Additional 24 h; weather observation age may be unknown |
| AQI | 30 min | Additional 24 h; nullable AQI/pollutants retained honestly |
| NWS | 10 min | Additional 24 h only for unexpired matching-location alerts; continuous expiry filtering required |
| News | 25 min browser | Additional 24 h; generated age >75 min or any partial feed is delayed; unchanged fetch never resets feed age |
| Markets | 5 min browser | Nominal additional 7 days; producer and per-row stale flags persist. Source stale >90 min for stored active session or >24 h for closed/unknown. Audited expired fallback remains possible, visibly stale with exact known age; no silent retention removal is approved |
| Currency list | 24 h | Additional 24 h; short static names list is metadata only |
| Currency rate | 12 h | Additional 24 h; reference date distinct from TTL; routine age check corrected under IG-04 |
| Prayer dated cache | 24 h | Audited additional 24 h is not permission for a past countdown or wrong context. IG-01 requires correct dates/future candidate; indefinite global backups cannot override identity/validity |

These are fresh windows plus additional stale allowances, not total lifetimes. Source-level staleness can precede browser expiration. Re-evaluate freshness during visible minute scans, expiry/date boundaries and resume, not solely when a new response arrives. Show source ages from original timestamps even if a backend publication is repeatedly downloaded.

**DI-06 — Refresh outcomes (P0, E+N; R03/R04).** Preserve coordinator order weather → AQI → US alerts → enabled prayer → enabled currency → news → enabled markets, deduplication, hidden routine-work suppression and affected-settings invalidation. Individual market checks remain public-file reads. Global feedback distinguishes: validated new source data, checked unchanged source, cached fallback, partial, failed/unavailable and skipped/disabled. A partial provider cannot contribute to a claim that all values refreshed. Keep existing compact `n/m` only if “n” is defined truthfully with partial/cached details separately; do not equate returned Promise success with full data freshness. Old manual summary must be superseded by the next check and qualified by current offline/error state.

**DI-07 — Missing and partial data (P0, E+N).** Validate required series/documents before accepting them. Nullable values stay null; no market zeroes, prayer guesses, weather interpolation, fabricated cross rates or realistic production mocks. Valid empty news/no-alert response differs from request failure; unsupported alerts differ from an empty successful US check. Market retained/missing rows remain identifiable. News partial feed indicates possible retained categories without false per-bucket precision. AQI can have pollutant data while AQI unknown. Prayer can have a valid today schedule but no valid tomorrow schedule/next prayer. Independent domains keep working when another fails.

**DI-08 — Cache trust and failure continuity (P0, N; R09).** Revalidate domain payload and context on cache read before presentation, including weather/AQI/currency paths whose generic envelope validation is currently insufficient. Keep original fetched/source timestamps on failed checks. Invalid entries are discarded or quarantined without crashing; matching valid retained data may continue. Future timestamp/corrupt date/unit/pair/schedule records must not silently become current. Storage unavailable/full must leave the session usable, with honest persistence feedback. This is a new hardening prerequisite for reliable presentation, not a claim that all current caches are validated.

**DI-09 — Data/privacy controls (P0, E controls + N corrected semantics; R09/R11).** “Clear cached data” must abort/supersede affected in-flight work, remove all domain response caches including prayer last-valid backups and remove corresponding in-memory fallback readings, then show empty/loading/unavailable until a later authorized coordinator/check result. It keeps location/preferences and NWS dismissal choices; explain these exclusions. No late completion may repopulate cleared data. Clear market cache does the same for market data only. “Reset to defaults” resets settings through existing migration/defaults and invalidates changed contexts; it is not a complete data erasure action and must not claim to clear dismissals/caches. No new wipe-all command is in scope. Explain browser-local storage and coordinates sent to providers; do not promise data never leaves the device. Preserve image URL/referrer safeguards and never put credentials in diagnostics.

**DI-10 — Provider compatibility and operational gates (P0, E boundary + N evidence gate; R07/R08/R11/R12).** Before launch, verify supported Frankfurter base/quote/default pair and date/rate correctness against its actual deployed-origin behavior; retain unavailable when unsupported. Verify public snapshots, intended provider usage/attribution/plan entitlement, default-origin CORS and base-path assets. No v1→v2/provider substitution, unofficial proxy, secret exposure, cadence/Actions permission change or new backend is authorized. Separate reviewed scope is required if compatibility cannot meet the product requirement. The market URL remains repository-specific until an explicit portability change is approved. Licenses/attribution and access results must be recorded as evidence, not presumed from the audit.

## Integrity prerequisites: audited R01–R04

Each IG requirement is **P0, N**. These are dependency acceptance contracts for separately scoped remediation before reliable world integration. This documentation task applies no fixes and does not prescribe provider rewrites. Reused normalization/polling remains outside the renderer.

| ID / finding | Required correction | Required proof before scene dependence | Blocks |
| --- | --- | --- | --- |
| IG-01 / R01 | Bind weather to units/location, currency to validated requested pair/base/date/rate, prayer backups to coordinates/timezone/date/method/school; reject future-context races and invalid/past next prayer. Unknown prayer method/school must not silently label a fallback calculation as the requested unsupported method | Delay/fail old/new requests across each context switch; reload with wrong-context backups; verify labels/countdowns/scene never adopt mismatched values. Invalid response base/negative rate/date fails validation | Weather/daylight, currency pavilion, prayer lighthouse; DI-02 and FR-03/FR-11/FR-12 |
| IG-02 / R02 | Immediately clear alerts on location/coverage change even when provider becomes disabled; age out expiry/end continuously and on resume; distinguish checking/none/unavailable/unsupported/cache; retain valid dismissal semantics | US→non-US→different US during an in-flight request; active alert expires without network; hidden-expiry resume; failure with/without valid cache | Every alert banner/dialog/signal and critical-alert escalation |
| IG-03 / R03 | Preserve truthful per-value provenance and source times, unknown metadata and partial outcomes; never label loaded/network/cache-success as live; do not advance network-success time on cache/error/cancel | Fresh cached weather, old static news, carried partial categories, stale/missing market row, unknown quote/observation timestamp and prayer cached response; compare HTML/world/status | All data-derived environment/status; DI-03/DI-04/DI-06 |
| IG-04 / R04 | Use elapsed currency freshness in mounted sessions; bound direct-fetch/body completion and provider sweep; reject all late/superseded/aborted writes including market cached fallback after abort; cleanup-safe stop/restart | Long-session TTL passage; a stalled body/direct fetch; StrictMode start/stop; hide/reconnect; rapid settings/enable changes; abort market cached fallback; no duplicates or newer-context loading/error/timestamp overwritten | Long-lived modes, provider refresh feedback and every scene subscription |

Proposed IG-04 deadlines: direct Fetch integrations (NWS, static news, currency, prayer) complete or fail within 15 seconds including body/schema processing per invocation; no new retry loop. Existing API-client paths retain transient-retry behavior but each provider invocation has a 30-second total ceiling, including backoff/body; a Retry-After beyond the ceiling becomes a deferred/rate-limited outcome, not an indefinite wait. A seven-provider manual sweep must settle within 210 seconds when online; progress appears within 200 ms and prior data stays readable. These N limits require review and tests before changing active request policy. Prayer's parallel today/tomorrow requests share its provider deadline. Cancellation must suppress publication regardless of whether underlying I/O terminates immediately.

## Data-driven environmental meaning

**EN-01 — Time and daylight (P1, V+N; F01/F06/F10).** Island illumination follows selected-location local time; valid sunrise/sunset refine broad morning/day/sunset/night cues. Missing sun times may use the existing broad local-time decorative approximation, disclosed as approximate in daylight detail, never a fabricated sunset reading. Invalid timezone uses DI-02's disclosed fallback. Device clock/timezone changes update clock/lighting coherently without camera movement; lighting is stylized, not astronomical proof.

**EN-02 — Weather and AQI (P1, V+N; F03/F04/F09).** Use only normalized supported condition groups (clear/cloud/rain/snow/fog/storm) for stylized clouds, light and bounded precipitation. Forecast probability is not current rain intensity; wind speed is not permission for a physical simulation. Last-known valid weather may retain an explicitly qualified atmospheric state; expired/unavailable/old-context data becomes neutral, not “clear weather.” A neutral treatment has no weather claim. AQI colors/haze, if used, are qualitative and subordinate to readable category/value; unknown AQI yields no measured pollution cue. Storm effects may not flash or convey unofficial alerts.

**EN-03 — Station signals (P1, N; F05/F07/F08/F11/F12).** Observatory may signal the official active alert level; signal station may indicate news availability/selection; pavilion may reflect accepted signed change with text equivalents; lighthouse may quietly indicate next valid prayer when enabled. None imply live transmission, new headlines, new quotes or a due prayer from stale/missing data. No continuously pulsing price/headline badge. Update static numeric text only on accepted data, never animated invented intermediate prices/times. Off modules keep architecture visible but have no false activity.

**EN-04 — Motion, blending and assets (P0 policy / P1 presentation, N; R05/R06/R11).** Data updates may blend decorative lighting/condition effects over 1–3 seconds with motion enabled; HTML values/status update immediately and blending does not claim intermediate meteorology. Reduced motion/Static uses instantaneous still-state updates. No motion crosses over text or reduces contrast. Locally hosted, provenance/license-recorded world assets must obey PF budgets and BASE_URL/subpath behavior; no mandatory third-party model/texture calls or added trackers. Asset failures use IN-10 fallback.

## State transitions and camera ownership

**IN-01 — Mode/selection state (P0, N).** Treat mode, selected station, settled chapter, camera activity, detail panel and modal state as separate observable concepts. Modal/hidden/renderer-unavailable suspension overrides camera activity. Mode transitions do not reload domain state, reset settings, remount provider polling or change URL/history. Initial/reload mode is Overview; transient camera/mode/disclosure state is not persisted. A mode control indicates selected state. Destination selection is immediate, with “Travelling to [station]” until settled; do not label the last readable panel as the new station while still showing old content.

| From / event | Destination and visible result | Camera / focus result |
| --- | --- | --- |
| Startup/reload | Overview, summary immediately, world loading/fallback independently | Static overview once available; no focus theft |
| Overview / station details | Overview + selected station's local detail panel | No travel; keyboard/tap invocation focuses heading, close restores invoker |
| Overview / Enter Journey | Journey at overview vantage, first chapter guidance | Wait for explicit next/scroll; focus Journey navigation heading/control |
| Any nonmodal mode / Visit station | Journey targeted station with matching detail | Cancel old travel, follow safe guided path or instant motion-off change; heading focus on settlement |
| Journey / direct station, Next/Previous or chapter scroll | Journey new target/chapter | Latest intent; no data refresh; rules below |
| Journey / Back | Previous completed visit from session-local visit stack, or Overview if none | Canceled/intermediate poses are not history entries; focus completed destination |
| Journey / Return to Overview or final chapter | Overview, close station details; retain data/topic/preferences | Cancel old path; stable overview; focus Overview control |
| Overview or Journey / Ambient | Ambient, close details, preserve summary/topic | Wide stable pose after bounded transition or instant motion-off; focus visible Ambient exit |
| Ambient / Exit Ambient or Escape outside nested UI | Overview; no automatic previous-Journey resume | Stable overview; focus Overview control |
| Any / Preferences or alert/provider modal | Same underlying mode, modal open | Cancel travel and freeze decorative camera effects; focus modal |
| Modal / close | Same mode/selected context; most recent data visible | No auto-resume; explicit Continue to station is required if travel was interrupted |
| Any / hidden | Same mode logically suspended | Cancel camera travel, stop decoration, no focus manipulation |
| Resume visible | Same mode with recomputed current time/validity; coordinator stale check | Remain still until explicit navigation, no elapsed tour replay |
| Any / world failure | Same logical mode, semantic station/content access in fallback | Cancel travel, safe surviving HTML focus; optional explicit Retry world |

**IN-02 — Camera motion/interruption (P0 cancellation / P1 paths, N).** A direct guided visit or mode reframe lasts 0.8–1.6 seconds, with a hard maximum of 2 seconds; motion-off switches instantly. Fixed paths must avoid passing through geometry or placing important text behind landmarks. Only one active camera intent exists. New target replaces prior intent from current pose, never queues a tour. An always-reachable Stop motion button while moving and Escape stop within 100 ms of handling input. Stop holds the current pose and keeps the last settled chapter/content; explicitly Continue to [target], another station, or Overview resolves it. Do not snap, continue inertia or silently finish after Stop.

Direct navigation, Stop, modal open, context loss, page hide and motion-policy change cancel scroll settling. A location/unit change does not move the camera; data context resets separately. Routine data refresh never triggers travel. Decorative light/weather loops may continue while a station is settled, subject to motion/visibility policy. A modal freezes camera activity; no modal may arrive after an obsolete camera completion and move focus out of the dialog.

**IN-03 — Focus and announcements (P0, N; R06).** Use labeled semantic HTML navigation, headings, time, links, buttons, disclosure states and modal roles. Canvas is decorative for assistive technology; equivalent station controls expose its actionable meaning. Do not duplicate each data value into an invisible constantly announcing scene tree. Focus stays visible and unobscured. Open modal → initial meaningful heading/close control → contained Tab/Shift+Tab → Escape/backdrop/close → originating surviving control. Nested provider modal closes to its invoker inside Preferences; Escape closes only the top layer.

Direct chapter activation focuses its settled heading; scroll changes do not steal focus. Station panels do not trap focus unless modal. Closing a panel/popover restores invoker; if missing, use same station's HTML control or Overview. Stop does not steal focus; Return to Overview focuses its control. Clock seconds/countdown/frame changes are not live announcements. Refresh completion/settled scroll chapter is a concise polite announcement once; newly severe/extreme alert uses one assertive announcement per newly received alert ID/severity escalation, without forced focus. Existing dismissals persist; rechecking unchanged data must not repeatedly announce it.

**IN-04 — Motion preferences (P0, E+N).** Effective reduced motion is OS prefers-reduced-motion OR the app's reduced-motion setting. An app toggle cannot override the OS. Static background also selects still atmosphere and instant camera transitions; Living/Subtle never overrides reduced motion. Preferences changes take effect during movement within 100 ms; retain the selected destination and present its still view immediately without animating the remainder. Reduced motion retains all modes/chapters/details; scroll selects chapters without camera interpolation. No parallax, auto-orbit, pulsing/particles or nonessential animated crossfades in this policy. Data/time text still updates. Re-enabling motion does not auto-resume an interrupted path.

## Input, scrolling and responsive access

**IN-05 — Scroll ownership (P0 semantics / P1 guided scroll, N).** Overview/Ambient do not bind wheel or touch pan to camera. Journey has a visibly labeled, focusable exploration region with scroll instructions and equivalent Previous/Next buttons. Only wheel/pan originating there controls chapter progress. Input stops for 200 ms → settle to nearest chapter pose within 500 ms, unless canceled; do not repeatedly advance from one gesture after settling. Exact path easing/distance belongs to later design; settlement and access guarantees do not.

News/forecast/market/prayer panels, Preferences and modals own their normal vertical scroll. At their ends scroll does not chain into Journey. Touch vertical panel swipes scroll content; scrolling is not interpreted as a tap. Browser pinch/zoom, text selection and browser/assistive navigation are preserved. On fallback/narrow/zoomed layouts document scrolling is allowed and never secretly navigates a camera. No page-level key/wheel listener may hijack an input/select/text field or modal. A focusable exploration region is not a keyboard trap: Tab always leaves it.

**IN-06 — Keyboard and touch equivalence (P0, N).** Tab/Shift+Tab follows clock controls → mode/station navigation → summaries/details → remaining controls in a logical order independent of physical landmark positions. Enter/Space activates buttons; Enter opens links. Chapter navigation group may use arrows for adjacent chapters and Home/End for first/last; scope these handlers to that group, not the document. Native scrolling keys operate focused panels/exploration region; buttons provide complete movement without scroll. Search/typeahead, settings tabs and selects retain their own keys. Escape priority: top modal → open popover/panel → moving camera → Ambient exit → Journey return to Overview. Ignore camera shortcuts while typing or operating native controls.

Touch has visible tap targets for each station, mode, disclosure, Stop/Return and exit; no hover-only data, drag requirement or motion-only navigation. Pointer hover highlights stationary landmark/associated HTML name; focus has an equivalent indicator; selected state persists independently. A landmark click is suppressed after a drag/pan gesture. No new global single-key shortcut is required.

**IN-07 — Alert escalation (P0, N; R02/R06).** For a matching-location valid undismissed NWS alert: Severe or Extreme is critical; Moderate/Minor/Unknown uses the ordinary persistent alert treatment without inventing severity. A newly received critical alert pauses camera movement, reveals alert controls in Ambient, and posts its official HTML headline/severity/location/expiry and source/cache qualifier. It does not change mode, rotate camera, take focus, auto-open a modal, flash or play audio. If another modal is open, leave its focus trap intact and provide the banner when that modal closes; announcement still identifies the event once. No banner floats over blocking modal controls. Dismissal is per stable ID with existing expiration/end semantics; a dismissed alert does not reappear on a recheck. All other valid alerts remain accessible via alert detail controls. Expiration/removal/context change clears its world signal within the IG-02 lifecycle gate.

**IN-08 — Browser history and return (P0, E baseline + N explicit behavior).** No router, URL deep link or history entry is added. Browser Back leaves the page as it currently does; it is never intercepted for station navigation. Journey Back uses only its local completed-visit stack, distinct from fixed-order Previous/Next controls. Return to Overview is available in all nonmodal world/HTML modes, including no-WebGL fallback. It cancels movement, closes local details, preserves data/settings, resets Journey visit stack and restores Overview controls. Modal closure happens first; its background controls are inert while open.

**IN-09 — Responsive/readability (P0, N; R06).** Verify Overview/Ambient summary at 1366×768, 1440×900, 1920×1080 and proposed 3440×1440 ultrawide in CSS pixels at 100% zoom. Keep primary readings within the initial viewport without document scrolling or clipping. Details use local scrolling/disclosures. Maintain text hierarchy and readable contrast in all day/weather scenes; resize world area/reflow overlays before shrinking text. Required summary content cannot collide with station controls or safe focus areas.

At smaller widths/heights or 200% zoom, prioritize semantic HTML, permit document scroll and offer direct station sections; do not enforce a fixed-height no-scroll canvas that clips content. At 320 CSS px width, required information reflows without two-dimensional page scroll (long identifiers wrap); optional world area may be static/omitted with explicit fallback description. Touch landscape/resizing retains current mode/selection without moving focus unexpectedly. At desktop size all four landmarks should remain recognizable, with exact overlap/framing validated later in rendered design evidence.

**IN-10 — Non-WebGL and recovery (P0, N; R05/R06/R10/R12).** If renderer capability is absent, context lost, lazy chunk fails or a critical model/texture cannot load, show a coherent still/DOM island treatment or neutral atmosphere plus full semantic summaries and station panels. Journey offers the same chapter ordering and direct controls as HTML sections, with no simulated promise of camera motion. Ambient remains informative with manual exit. Data acquisition/settings/refresh continue independently. State why the world is unavailable and offer explicit Retry world without clearing data or reloading providers; no automatic retry loop. If retry succeeds, restore the current mode/station's stable pose without an automatic trip. Preserve whole-app fatal recovery separately (FR-15).

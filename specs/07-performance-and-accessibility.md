## Scope and measurement policy

**PA-01 — Preserve usability before graphics.** The page is a client-rendered SPA, not SSR. “Initial HTML usability” means the first rendered semantic clock, navigation, summary regions and truthful loading states; it does not promise provider results before their requests complete. No renderer import, shader, asset or font is on the critical path for essential controls. A failed renderer never removes these elements. Keep domain timing independent of frame rate. No production features or performance tooling is implemented by this document.

Budget revision requires a recorded reason, affected requirement, owner approval and comparable before/after measurement. A slow reference machine cannot be declared unsupported after it fails without explicit scope review. Functional fallback is required everywhere within the HTML browser floor, but does not count as passing P1 3D on reference hardware. Reduced motion is an accessibility policy, not a performance failure. Test low and standard tiers explicitly.

**PA-02 — Browser support is capability-tested.** Proposed release support: current and immediately previous stable major of Chrome, Firefox and Safari at release, on operating systems still supported by those browser vendors. Record exact build versions at M00 and freeze the acceptance matrix for that release. No arbitrary version number is guessed from the date. Chrome/Firefox run on Windows 11 and macOS; Safari runs on supported macOS. Edge is supplementary inherited coverage, not a substitute for Firefox. Browser tools/emulation alone cannot certify a GPU class.

Capability exclusions: Three WebGLRenderer needs **WebGL 2**, not WebGL 1. WebGPU is neither required nor a fallback. No mandatory floating-point render targets, compressed GPU format, timer query, battery API or device-memory API. Lack of a performance/memory extension is reported as an instrumentation limit. No IE/legacy browser or offline-installed shell guarantee is added. HTML itself still depends on the existing app's JavaScript/ES2022 and CSS platform support. ### Quality policy — PA-06

Start standard only on eligible desktop with successful capability/resource checks; otherwise low or still. No device blacklist or assumed device-memory API. Sample frame statistics in renderer-local buffers; publish quality changes at most once per five seconds, never each frame. Proposed sustained downgrade trigger: p95>40 ms over two consecutive five-second active windows, excluding hidden/loading/compile; immediate downgrade on hard resource-cap failure. Drop sea/reflection detail, props and shadows first, then DPR/geometry, then still. Never hide readings, raise text contrast risk or alter domain cadence. Do not auto-upgrade repeatedly; quality holds for the session until explicit world retry/reload or a reviewed future user control. A renderer attempt may choose low on retry. No new settings migration.

Still is functional preservation with explanation. Reference-device standard→low can pass if final P1 identity and all hard budgets pass; automatic still because of sustained failure on A/B remains failed P1 evidence. Zero motion still frames can be correct for an accessibility test without failing P1 art. Provisional trigger constants are implementation targets pending review and measured vertical-slice behavior.

## Verification harness and evidence architecture

**PA-08 — Add only the tools needed at implementation time.** Vitest is installed; browser E2E/accessibility/performance runners and a 3D authoring/optimization suite are not established. Chrome/Safari app bundles were found in `/Applications`; Firefox was not found there. This does not prove executable browser access or another install's absence. Do not install a runner or claim browser testing occurred in this documentation session.

At M00 choose an available browser capability for local screenshots/profiling; if deterministic automation is needed, propose/pin Playwright as a dev-only runner and optionally axe-core for automated a11y checks. These are candidate verification tools, not selected runtime dependencies. Confirm install scope/availability before use. Playwright WebKit is useful automated coverage but **does not replace shipping Safari** on reference hardware. No Chrome DevTools MCP assumed from an installed skill. Manual browser/native profiler tools remain valid if evidence is repeatable and recorded.

Controlled fixtures must be test/DEV-only and visibly identified. Test tables cover each FS-01 state for every domain, both full and partial payloads, context races, US/non-US alert switching, local midnight/DST, invalid timezone, after-Isha/missing tomorrow, FX TTL, offline/no cache, corrupt storage/clear races, failed images, renderer failures and incomplete DEV overrides. Reuse existing producer/provider tests. Never activate mock production data to make a screenshot look complete.

For every result capture: requirement ID, revision, date/tester, status pass/fail/blocked/not run, exact device/OS/browser, viewport/DPR/buffer, quality/effects/assets/hash, power/thermal conditions, fixture/provider context and expected/observed outcome. Proposed future evidence root `plans/evidence/<milestone>/` holds small screenshots/JSON summaries; large traces/video may be referenced by stable artifact path with digest. No evidence files exist merely because a path is named here. Redact URLs containing sensitive query values; never capture credentials. No automatic upload/telemetry.

Three instrumentation reports calls/triangles/object counts, not exact GPU allocation. Include all passes and disposal; use conservative inventory plus observed process measurements. Shader variants precompile before declaring ready, with startup checks and fallback; runtime failure injection tests verify the bridge into HTML. `WEBGL_lose_context` is a test aid if supported; missing extension requires a controlled failure event harness and a documented real-context-loss verification gap.
